# ドキュメント

プロジェクトのドキュメントをこのフォルダに格納します。
必要になった時点でMarkdownファイルを追加してください。

## 記載方針

- ルートのREADMEには、プロジェクト概要、現在の利用方法、起動・停止・テストの基本手順を記載します。
- 開発ルールは[開発ルール](development-rules.md)と[ライブラリ利用ルール](dependencies.md)で管理し、ルートのREADMEには本文を記載しません。
- Issueごとの実装経緯、判断理由、遭遇した問題と対応、検証結果、未完了事項は`docs/issues/`に記載します。
- 作業記録は`issue-<番号>-<概要>.md`という名前で作成し、対象Issueと記録日を明記します。実施済み・未確認・未実施を区別し、後から確認した結果は日付を添えて追記します。

## その他のドキュメント

開発手順、コミット・push、コメント、定数の管理方針は[開発ルール](development-rules.md)を参照してください。

ライブラリ・ツールチェーンの導入と固定方法は[ライブラリ利用ルール](dependencies.md)を参照してください。

| ファイル名の例 | 内容 |
| --- | --- |
| architecture.md | システム構成・設計方針 |
| development.md | 開発環境の準備・作業手順 |
| api.md | API仕様 |
| review.md | AIレビュー結果・人間による検証・対応方針 |
| demo.md | デモ手順・学習成果・改善点 |

起動・停止の基本手順はルートの[README.md](../README.md)に記載し、詳細な補足をこのフォルダにまとめます。
