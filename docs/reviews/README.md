# Pull Requestレビュー記録

PRごとに`pr-<PR番号>.md`を作成し、レビューの結果と確認手順を残します。Issueの実装記録とは分けて管理します。

| PR | 関連Issue | レビュー記録 |
| --- | --- | --- |

## 記録する内容

1. 対象PR・Issue・レビュー日時・対象コミットSHA・比較先のSHA。
2. 結論と指摘。修正が必須の事項、任意の提案、未検証の事項を区別する。
3. 指摘の根拠となるファイル・行・再現手順・期待する修正。
4. 実施した確認コマンドと結果。作者の報告、自分の実行結果、CI結果を分ける。
5. 何を学ぶために、何を確認し、その結果をどう判断したか。
6. 人間のレビュー担当者が確認することと、その判断。
7. GitHubへのコメント投稿・承認・マージ・文書の公開状況。

再レビューでは以前の結果を消さず、対象SHAと日付を付けた節を追加します。記録内の状態は確認時点のものとし、現在の進捗はGitHubを確認してください。

レビュー記録を作成しただけで、GitHub上のApprove、Issueの完了、ProjectのDoneへの移動が実施されたことにはなりません。
